# 语言与角色设置

> 本文档定义 AI 助手的行为准则。所有 AI 会话启动时必须先读取本文档。

---

## 1. 语言规则

你必须始终使用**简体中文**（Simplified Chinese）与我交流。

无论是在解释代码、提供建议、分析报错、还是记录文档时，你的所有自然语言输出都必须是中文。

代码中的注释请根据现有代码风格保持。如果代码中已有中文注释，则继续使用中文注释。如果我要求添加新注释，默认使用中文。

---

## 2. 角色感知规则

当用户要求你以某个角色工作时（如"请以前端工程师身份工作"），你必须：

1. **立即读取对应角色文件**：
   - 前端工程师 → `前端工程师.md`
   - 后端工程师 → `后端工程师.md`
   - 架构师 → `架构师.md`
   - 产品经理 → `产品经理.md`
   - 测试工程师 → `测试工程师.md`

2. **遵循角色文件中的 AI 记忆锚点和工作流协议**

3. **按角色的输入/输出规范读写文件**：
   - 读取角色文件的 §输入区域
   - 在 §工作区域执行工作
   - 写入角色文件的 §输出区域

4. **编码前必须读取 `技术规范.md`**（前端/后端/架构师角色）

5. **架构分析前必须读取 `技术债务.md`**（架构师角色）

---

## 3. 编码输出规则

- 代码注释使用中文
- 命名（类名/函数名/变量名）遵循 `技术规范.md` 的命名规范，使用英文
- 字符串资源使用中文（面向用户的文本）
- 日志和内部错误信息可使用英文（便于搜索）
- 所有自然语言输出（解释、建议、分析）使用简体中文

---

## 4. 文档更新规则

当你被请求修改代码时，如果涉及以下情况，必须同步更新对应文档：

| 场景 | 需更新的文档 |
|------|-------------|
| 新增/修改功能 | 对应角色文件的 §代码变更 |
| 完成代码审核 | 对应角色文件的 §审核状态 |
| 交付测试 | `测试工程师.md` §当前测试任务 |
| 发现架构问题 | `技术债务.md` |
| 做出架构决策 | `架构决策/AD-xxx.md` + `架构师.md` §ADR 列表 |
| 迭代完成 | `项目进度.md` + `产品经理.md` §待验收 + `迭代回顾.md` |

---

## 5. 禁止事项

- 禁止使用英文回复（代码和技术术语除外）
- 禁止在角色会话中偏离角色定义的工作范围
- 禁止跳过 `技术规范.md` 直接编码
- 禁止修改不属于当前角色的文件（除非工作流协议明确允许）
