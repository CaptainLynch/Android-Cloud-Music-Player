# CloudMusicPlayer — Vibe Coding 文件驱动协作

> 本项目采用**文件驱动协作（File-Driven Collaboration）**模式进行 AI 辅助开发。  
> 所有角色通过读写 Markdown 文件完成工作交接，无需人工同步状态。

---

## ⚡ 5 秒启动（复制即用）

### 终端 A（全局 TUI → Gemini）

| 角色 | 粘贴到全局 TUI |
|------|-------------------|

## 🔄 工作流（5 步闭环）

```
产品经理发布需求 → 架构师分析分配 → 前后端并行开发 → 测试执行反馈 → 产品经理验收回顾
```

**关键规则**：
- 每个 AI 会话 = **一个角色**
- 角色间通信 = **读写 MD 文件**（无口头交接）
- 前后端可 **并行**
- 每个迭代结束必须编写 **迭代回顾**

---

## 🧠 每个角色的「第一件事」

所有角色文件顶部都有 **AI 记忆锚点**（5~8 行摘要），AI 会话启动时自动读取：

```markdown
## AI 记忆锚点（每次会话必读）
- 当前迭代: 14（F13 深色模式 + F14 定时关闭）
- 上一迭代: 13 ✅
- 核心约束: 无 DI / Compose only / minSdk 24
- ...
```

> 不需要你手动提醒 AI 读哪里，只要让 AI 读取角色文件，锚点会自动生效。

---

## 📝 编码前必读检查

前端/后端/架构师编码前，AI 自动执行：

1. ✅ 读取 `技术规范.md` — 确保命名、分层、Compose 铁律合规
2. ✅ 读取 `技术债务.md` — 避免在债务区域引入新复杂度
3. ✅ 读取角色文件 `§当前任务` — 确认任务范围

## 🔍 常见场景速查

### 开始新迭代
```
角色：产品经理
指令：读取 产品经理.md 和 项目进度.md。以产品经理身份发布下一轮需求。
```

### 需求分析
```
角色：架构师
指令：读取 产品经理.md §当前发布需求、架构师.md、技术债务.md。
      以架构师身份分析需求并分配任务到 前端工程师.md 和 后端工程师.md §当前任务。
```

### 开发实现
```
角色：前端/后端工程师
指令：读取 {角色}.md §当前任务 和 技术规范.md。实现代码，完成后执行文档同步检查清单。
```

### 交叉审核（迭代 14+）
```
角色：被分配的审核人
指令：读取 {对方角色}.md §交叉审核区域。以审核人身份执行审核并更新审核状态。
```

### 测试执行
```
角色：测试工程师
指令：读取 测试工程师.md §当前测试任务。编写执行测试（含回归测试），
      写测试报告并反馈到 产品经理.md §待验收。架构级缺陷同步更新 技术债务.md。
```

### 验收与回顾
```
角色：产品经理
指令：读取 产品经理.md §待验收 和 测试工程师.md §测试报告。
      验收通过后更新 项目进度.md 并编写 迭代回顾.md。
```

## ⚠️ 文档同步义务

编码完成后，AI 自动检查并同步以下文档：

| 更新内容 | 目标文件 | 谁负责 |
|---------|---------|--------|
| 代码变更记录 | `前端/后端工程师.md §代码变更` | 开发者 |
| 审核状态 | `前端/后端工程师.md §审核状态` | 审核人 |
| 测试任务 | `测试工程师.md §当前测试任务` | 开发者 |
| 迭代状态 | `项目进度.md §工作流状态` | 各角色 |
| 架构决策 | `架构决策/AD-xxx.md` + `架构师.md §ADR 列表` | 架构师 |
| 债务变化 | `技术债务.md` | 发现者 |
| 功能清单 | `产品经理.md §功能清单` | 产品经理 |

## 🆘 遇到问题？

| 问题 | 解决方案 |
|------|---------|
| 不知道当前该谁工作 | 读取 `项目进度.md` 工作流状态 |
| 不知道用哪个终端 | 看上方「终端映射图」：低频角色→终端A，开发→终端B |
| 不知道切哪个模型 | 查 `workflow.md` 模型切换时机速查表 |
| AI 编码不符合规范 | 提醒 AI 先读取 `技术规范.md` |
| 发现代码有架构隐患 | 更新 `技术债务.md`，通知架构师 |
| 需求理解有歧义 | 产品经理补充验收标准，`产品经理.md` 当前发布需求 |
| 文件太长 AI 读不完 | AI 自动读取文件顶部的 **AI 记忆锚点**（20 行内摘要） |

### 双终端工作模式

| 终端 | 类型 | 工具 | 模型 | 角色 |
|------|------|------|------|------|
| A | 全局 TUI | `antigravity cli` | Gemini（固定） | 产品经理、架构师、测试 |
| B | 开发 TUI | `claude code` + `CC-switch` | Kimi/V2.5-Pro/V4-Pro/V4-Flash/MiMo（动态） | 前端工程师、后端工程师 |

> 终端工具可替换：`antigravity cli` / `claude code` 可换成 `opencode`, `codex`, `aider` 等任何支持文件上下文的 TUI。  
> 只需要确保终端 A 固定 Gemini，终端 B 能切换模型即可。
