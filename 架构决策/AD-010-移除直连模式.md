# AD-010: 移除直连模式，统一为代理模式

**日期**: 2026-05-18
**状态**: 已接受
**决策**: 删除 F15 直连模式相关代码（加密模块、直连 API、策略模式），仅保留代理模式访问网易云 API

---

## 背景

迭代 12 中 F15 降级（AD-008）将歌单接口强制走代理，但保留了直连模式的代码和 UI 切换。迭代 12 回顾中指出"F15 降级是临时方案"，需要在后续迭代中彻底解决。

## 原因

1. **维护成本高**: 直连模式需要维护加密模块（CryptoUtils、LinuxApiCrypto、WeApiCrypto），网易云 API 加密算法变更时需要同步更新
2. **稳定性差**: 直连模式在歌单接口上表现不稳定，频繁出现鉴权失败
3. **代理模式已验证**: F16 部署的代理服务器运行稳定，能满足所有场景需求
4. **代码复杂度**: 双模式策略增加了 NeteaseRetrofitClient 和 NeteaseViewModel 的复杂度

## 影响

- 删除 15 个文件（`network/crypto/` 目录、`NeteaseCookieJar.kt`、`NeteaseDirectInterceptor.kt` 等）
- 修改 6 个源代码文件（简化 NeteaseRetrofitClient、NeteaseApiService、NeteaseViewModel 等）
- 清理 2 个测试文件
- 用户不再需要在设置中切换直连/代理，降低使用复杂度

## 替代方案

| 方案 | 评估 | 结果 |
|------|------|------|
| 保留双模式，仅歌单走代理 | 维护成本不降低，代码复杂度不变 | 放弃 |
| 直连模式换用其他加密方案 | 需要研究新加密方案，不保证稳定 | 放弃 |
| **完全移除直连，统一代理** | 简化代码，代理已验证稳定 | **采纳** |
